Security and access control

Who the app thinks you are, what that lets you do, and how it refuses everything else.

Think of a building with one entrance. At the door there is a badge reader. Inside, some rooms are open to everyone, most need your badge, and the ones that change anything need a second chit as well — proof that the request came from your own signed-in browser and not from a page some other site showed you. Two development-only side doors exist, and the building refuses to open at all if they are left unlocked.

What the fake header actually becomes

Worth being precise about, because it is the one place where a caller can choose their own identity. In Development only, the header value is trimmed and lower-cased, and if it has no @ an @example.com is appended src/PoMiniGames.API/Features/Auth/FakeAuthHandler.cs:72. That value becomes the name identifier, the object id, the name and the email claims src/PoMiniGames.API/Features/Auth/FakeAuthHandler.cs:75. A missing or empty header is not an error — it simply produces an anonymous result src/PoMiniGames.API/Features/Auth/FakeAuthHandler.cs:57.

Why this is safe in Production. It is not that the handler is careful — it is that the scheme is never registered there, and the startup validator turns a misconfiguration into a failed boot rather than a silent hole.

The second token: CSRF

Signing in proves who you are. It does not prove that this particular request came from your browser rather than from a page some other website convinced your browser to load. That is what the antiforgery token is for.

The checklist

Already in place

  • One composite scheme, one decision point per request.
  • Two development-only schemes, both refused in Production at boot.
  • CSRF token on every state-changing /api request.
  • Authorization on one group and on every hub.
  • Per-endpoint rate limits, plus two application-level ones.
  • Signed play sessions bound to game and identity.
  • Server-side replay for the two games that can be replayed exactly.
  • Managed identity and Key Vault — no key in source.
  • Data export and erase for the caller's own identity.

Worth knowing

  • Hub state is in server memory, so a restart clears live lobbies and matches.
  • Rate limits are per partition key, which follows the caller's identity where one exists.
  • The integrity guard can run in Observe mode, where a bad score is logged but allowed.
  • Public dossier data, health probes and the CSRF token endpoint are deliberately anonymous.
  • Nothing here replaces transport security; the tokens are bearer credentials.
